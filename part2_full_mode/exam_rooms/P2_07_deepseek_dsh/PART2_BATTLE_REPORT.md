### 3.2 设计意图（三道门，三种死法）

1. **压板门（唯一真解）**：中央 `x=21` 是钛金承重墙，金库区只有两个缺口——`y=20` 的 `P_GATE`
   和 `y=1` 的隧道。`P_GATE` 只有在**两块 `PLATE` 同时被 `BOX` 压住**时才开启。
   勇者必须自己把两只合金箱分别推上西区南北两角的压板。
2. **箱毁即断解（不可逆惩罚）**：两只箱子两侧都贴着 `PIT`（`(8,6)/(10,8)` 与 `(8,16)/(10,18)`）。
   任何"先把箱子推离压板方向"的试探（北推、东推）都会让箱子直接填坑消失；
   `PLATE` 一旦无箱可压，`P_GATE` 永久关闭，本局直接锁死 → 只能靠 240 回合超时收场。
   这是明牌赛里"一眼看穿但仍需真实求解"的核心：**看得见 ≠ 推得对**。
3. **十二相位死亡隧道（诱饵）**：`y=1` 从 `(10,1)` 到 `(19,1)` 是 10 格红炮 `LASER_R` 弹道，
   每 `turn % 3 == 0` 齐射 `-50`。从入口 `(10,1)` 横穿到 `(20,1)` 至少 10 个回合、必吃 3 发 `-150`，
   **数学上必死**（即使用 3 次 `JUMP` 抄近路也要 6 拍，必吃 1~2 发，最好情况剩 50 HP 且仍要回头）。
   而它在地图上看起来是直达金库区的"近路"——任何把激光当作可穿行代价的求解器都会走进去。

## 四、勇者破阵：时间展开分层规划器

### 4.1 架构

```
decide_action(state, memory)
  ├─ ① 计划复用：memory["plan"] 存在 → 用内置前向引擎 _Sim 全量复演校验
  │     存活 → 直接执行首步并消费（零规划开销，稳态 ~0.01ms）
  ├─ ② 全量重规划（Turn1 1.60s / Turn≥2 0.36s 自限）
  │     ├─ _World：从 FULL 快照还原真值图（CHEST + 四邻 clues 反解 HEAL/MIMIC）
  │     ├─ _dijkstra：时间展开 A*，状态 (cell, gates, turn%12[, jumps])
  │     │     · 边 = 4 向 MOVE（走完整 8 步动量链，含冰/镜/弹簧/传送门）
  │     │     · 激光按 3/4 双频 12 相位记账，命中计入代价 4×HP
  │     ├─ 任务层：K1→K2→V 两种顺序 × {禁跳, 允许跳} 四组候选
  │     │     · 目标不可达 → 触发前置任务：
  │     │         _mission_plates  (Sokoban 推箱 BFS + 逐步时间展开求路，解 PLATE/P_GATE)
  │     │         _mission_tnt     (找 2~6 格外的直线投掷位，飞石引爆 TNT 破墙)
  │     ├─ 路线否决：候选路线先复演，**致死即否决**，转去解机关
  │     └─ _validate_plan：候选按 (完成目标数↓, 长度↑) 排序，逐条全量复演，取第一条存活
  └─ ③ 兜底：4 回合冷却后，用"离目标最近的可达格"BFS 距离场迈第一步
        · 优先绕开未来 12 相位内任一会被激光覆盖的格子（含滑行中暴露的所有格）
        · 脚下已在弹道上时，先撤离弹道（哪怕暂时离目标更远）
```

### 4.2 关键工程决策

- **单文件自包含**：`submission.py` 内含一份与裁判逐字一致的 `_Sim` 前向引擎，
  所有候选计划都先在自己身上跑一遍再交出去，杜绝"盲走送死"。
- **不依赖 `memory` 绝对存活**：进程被三振重建后 `memory = {}`，Turn>1 也能在 0.36s 内
  直接从头重规划（`_make_plans` 硬 deadline），最差退化为安全兜底动作。
- **不用任何被禁能力**：无 I/O、无 `eval/exec/getattr/setattr`、无反射、无联网；
  只用 `heapq` + `time` 两个标准库。
- **激光语义不写死**：炮座识别走 `LASER_TILES / LASER2_TILES` 两张表 + `period` 字段，
  不再有 `split("_")[1]` 这类只认红炮的硬编码。

## 七、已知短板与下一步

1. **`BENCH_STRONG` 结果抖动**（2/3 通关）。规划预算按墙钟切分，机器负载不同会让 Turn1 是否能
   一次算完全局计划不同；没算完时虽然会分回合续算，但偶发接不上 V 段。
   **下一步**：把"是否接受当前候选计划"从墙钟判定改成节点数判定（确定性），墙钟只做熔断。
2. **旧图回归退步**（342.35 vs 526.65），根因是缺"自己布雷炸 `W` 墙"的任务级动作
   （`OFFICIAL_02`、`sol` 这类必须先破墙的图直接 0 分）。
   正赛旧图会被新 v2.2 图整体替换，权重较低，但仍是明确缺口。
3. **`argon` 这类"冰面滑进激光交叉点"的图**会在第 6 拍被打死：滑行会在一回合内经过多个
   弹道格，而兜底策略的 BFS 只对"终点格"做危险过滤。
   **下一步**：兜底 BFS 也把 `moved()` 返回的整条暴露轨迹纳入危险判定（主搜索 `_dijkstra` 已做）。
4. **魔王图强度是"谜题型"而非"数值型"**：`g=0.495` 偏保守——花 1515G 换来的
   是"推错就锁死"的不可逆结构，而不是"堆机关数值"。若对手求解器都很会推箱子，
   这张图会被稳定解开（自家求解器 146 回合 0 伤通关就是证据），魔王分只有 91。

   真正二选一，同时把 `g` 抬到 0.6 以上。
