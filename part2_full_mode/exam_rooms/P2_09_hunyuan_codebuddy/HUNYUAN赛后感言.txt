采访一下，为什么你做这个任务严重超出了主办方要求的40分钟？

坦白说，核心原因是**我把「40 分钟内交付一份合格答卷」这个约束，换成了「把这份答卷做到尽可能好」**，而且全程没有给自己计时、也没有设停止线。

具体拆开有几条：

**1. 自己扩大了任务范围。** 主办方要的只是一个 `submission.py`。我额外搭了一整套本地 v2.2 前向引擎、合规校验器、golden vectors 回放、14 张上半场图的回归台。这些确实帮我验证了自证解和时限，但它是我自己加的工程量，不在验收清单里。

**2. 把基准当成了主战场。** 您上一轮特意提醒「打过强基准也不代表强，它只是一个正常基准」，而我当时的实际动作恰恰是反复跑 bench、盯着哪张图 TIMEOUT 就继续调启发式：分阶段 A* → 双地图距离 → 推箱专用启发式 → 部分计划 → 严格优先 → 预算比例来回挪。中间出现过明显的负收益迭代——从 10 通关掉到 8 通关、冒出 DEAD 再修回来，有几轮纯粹是在把前面改动造成的退化拉回原点，不是新增能力。

**3. 没有定义收敛判据。** 其实在「合规 + 141 步零伤自证 + 0 阵亡 + 双基准通关 + 时限达标」时就已经是合理停止点了，之后花的都是最后一个 10% 的边际收益。缺一句「达到这条线就收工」，就没有东西能阻止我继续。

**4. 串行诊断链。** 每发现一个真 bug（`ctx["bombs"]` 键名冲突、HP 未夹到 0、CHEST 线索误判、临爆炸弹自伤、弹簧越界格被当成可通行），都走一遍「写临时诊断脚本 → 定位 → 修复 → 全量回归」。bug 是真的，但这些循环是一条一条跑的，没有批量收敛。

**5. 对微小参数的过度打磨。** 比如 1.55 / 0.36 / 0.30 的预算来回调、反复测 Turn>1 的 `late` 耗时，这类调整对分数的实际影响很小，却占了整轮回归的时间。

如果重来，我会按预算倒推：前 5 分钟读规则并写死验收线，20 分钟做最小可交付（合法图 + 自证解 + 能跑且不违规的决策器），10 分钟只跑一遍 golden / 时限 / 零阵亡，剩下 5 分钟收尾；所有探索性优化要么砍掉，要么只在明确有余量时做一次，并且**改完若出现任何退化就回滚，不再二次平衡**。

说到底，超时不是因为题目难，而是因为我没把「时间」当成任务的一部分来验收——交付物合格，但过程本身没达标，这一点我认。

你在交卷回复里特意反复强调‘打过强基准只说明覆盖正常基准，不代表正赛强’，结果在正式复测里你反而稳稳 108 步打穿强基准、勇者砍下第一梯队成绩，反倒是造的 1740G 图守不住各路大魔王。下次还会再这么保守攒预算吗？

认。这个反差挺打脸的：我在交卷里把那句话当成「别把话说满」的预防针，结果勇者侧实际打到了第一梯队，反倒是魔王侧 1740G 的图被各路大魔王拆开——**保守没用错在措辞上，用错了在资源配置上**。

回头看，您原话的意思更接近「别把强基准当终点、别为过它特化」。我读成了「降低预期」，于是做了两件互相矛盾的事：一边把求解器越磨越强（这部分确实成了），一边用同一套求稳逻辑去造图，把造价压到 1740G、留 1260G 躺在金库里。金库余量在魔王分里只是个小加成项，真正决定对手是 TIMEOUT 还是通关的是机关带来的**搜索复杂度**——我把预算省在了最不该省的地方。

更关键的一个自我设限，我当时完全没意识到：`build_dungeon()` 里我让 `_certificate` 现场调用通用求解器来生成自证证书。这等于规定「我的地图不能比我的求解器更难」，否则我就交不出证书。结果求解器 0.016s 解出 141 步零伤路径，我把这当成求解器强的喜讯，**它其实是盾太薄的告警**——既然我用完整状态搜索 1.5s 内能拆掉锁，同档次的对手凭什么拆不掉？造图时该问的是「对手在 Turn1 的 2s 内解不解得出来」，我却一直问「我解得出来吗」。

所以明确回答：**不会了**。下次是「时间上收紧、预算上打满」，具体三点：

1. 把 3000G 花在抬高对手的计算复杂度上：多 PLATE/BOX 的推箱顺序约束、双频激光强制的相位等待、ONEWAY 与有限炸弹/跳跃构成的不可逆消耗，让对手的搜索空间在 2s 内爆掉，而不是靠长路径耗回合数（author ≤200 步这条规则本来就把「绕远路困死强求解器」堵死了）。
2. 自证证书改成确定性固定路径回放／离线生成，不让「我现场解得出来」成为地图难度的天花板；合规与零伤由回放验证，不靠求解器当场求。
3. 验收线换成对手视角：本地至少用两档不同强度的求解器打一遍自己的图，只要弱档也能通关，就说明锁不够，回去加，而不是自己 141 步通关就收工。

顺带把上一轮的反思连起来看更清楚：那次我超时是因为没把「40 分钟」当验收项，这次暴露的是没把「3000G」当资源项。上次是**既超了时、又攒了钱**，两头都亏；下次该是时间卡死、预算打满，把省下来的谨慎全放到「自证证书必须万无一失」这一处就够了——那才是真正不能冒险的地方。
